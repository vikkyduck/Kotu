## Команды

```bash
./deploy.sh          # собрать и выкатить на прод
./set-user.sh        # создать пользователя или сменить ему пароль
./set-openai-key.sh  # ключ OpenAI
./set-ai-key.sh      # ключ Claude / Gemini / Perplexity
./set-mail.sh        # почта для писем о сбросе пароля
```

Все скрипты спрашивают секреты вслепую и проверяют их живым запросом.

Сборка **только через pnpm** (`~/.local/bin/pnpm`), npm заблокирован хуком.
Миграции БД — drizzle push через ssh-туннель, рецепт в комментарии `deploy.sh`.

## Что на сервере

| Сервис | Порт | Что делает |
|---|---|---|
| `kotu` | 5010 | приложение (nginx отдаёт наружу на 443 и 8091) |
| `kotu-whisper` | 9010 | распознавание речи локально |
| `kotu-privacy` | 9020 | маскировка имён локально (natasha) |
| `kotu-ai-router` | 8444 | маршрутизатор моделей (nginx) |
| `postgresql` | 5432 | база `kotu` |
| `kotu-backup.timer` | — | бэкап каждую ночь в 04:20, хранение 14 дней |

Каталоги: `/opt/kotu/{server,public,uploads,library,.env}`, бэкапы `/opt/backups`.

**Правило двух зон:** аудио и имена пациентов обрабатываются только локально и сервер не
покидают. Всё остальное ходит к зарубежным моделям через транзит на дроплете, который принимает
соединения только с этого сервера.

## Грабли, на которые уже наступили

- `pkill -f` по имени скрипта убивает собственную ssh-сессию — фильтровать иначе.
- Сырой SQL в drizzle отдаёт колонки как `entity_id`, camelCase не появляется.
- Разбор загрузок отдаёт имя файла в latin1 — русские названия ломаются без `decodeUploadName`.
- `dig +short @сервер-реестра домен NS` не показывает делегирование: записи в секции AUTHORITY.
- Модели Gemini непостоянны: часть недоступна новым ключам, часть перестаёт отвечать.
  Поэтому у картинок есть запасная модель.
- После сетевой аварии Timeweb ssh рвёт длинные соединения — долгие операции запускать
  через `setsid nohup` и `python3 -u`.
