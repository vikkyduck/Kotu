## Команды

```bash
./deploy.sh          # собрать и выкатить на прод (код, службы, скрипты, сайты nginx)
./set-user.sh        # создать пользователя или сменить ему пароль (сбрасывает ВСЕ сессии)
./set-mail-postbox.sh # ключ Yandex Cloud Postbox для писем о сбросе пароля
./set-ai-key.sh      # запасной платный ключ OpenAI - сейчас не нужен (MODEL_ON_LIMIT=wait)
./ops/pull-backup.sh # забрать бэкап с сервера к себе на компьютер
pnpm test            # прогнать тесты
```

Все скрипты спрашивают секреты вслепую и проверяют их живым запросом.

Сборка **только через pnpm** (`~/.local/bin/pnpm`), npm заблокирован хуком.
Миграции БД — drizzle push через ssh-туннель, только вручную: дамп → push → `systemctl restart kotu`
(порядок и почему — `DEPLOY.md`, «Миграция схемы»; рецепт туннеля — в конце `deploy.sh`).

## Переезд на другой компьютер

**Бэкапы переносить не нужно** — папка `~/kotu-backups` это копия, а не оригинал.
На новом компьютере она восстанавливается одной командой `./ops/pull-backup.sh`.
Переносить нужно не данные, а ДОСТУП к серверу.

Что забрать со старого компьютера (напрямую — флешка, AirDrop, кабель; не почтой
и не через облако):

1. `~/.ssh/id_ed25519` и `~/.ssh/id_ed25519.pub` — этим ключом открывается и сервер,
   и GitHub. Ключ без пароля, поэтому сам файл и есть доступ.
2. `~/kotu-backups` — если хотите сохранить историю дампов. Свежий бэкап
   всё равно приедет заново; с 23.09.2026 сервер дампы тоже не удаляет, но копия
   на компьютере — единственная вне сервера.

Что переносить НЕ нужно: код (он на GitHub), секреты (живут в `/opt/kotu/.env`
на сервере и попадают в бэкап), настройки платформы (в базе на сервере).

На новом компьютере:

```bash
mkdir -p ~/.ssh && cp <ключ> ~/.ssh/id_ed25519 && chmod 600 ~/.ssh/id_ed25519
ssh root@СЕРВЕР "echo вход работает"
git clone git@github.com:vikkyduck/Kotu.git ~/kotu
cd ~/kotu && pnpm install
printf 'SERVER_HOST=СЕРВЕР\n' > ops/server.local
./ops/pull-backup.sh
```

**Если ключ потерялся.** ssh пускает только по ключу; без ключа — консоль восстановления в панели
DigitalOcean (Droplet → Access → Recovery Console). Для неё нужен пароль root: проверьте его в
панели ДО того, как стирать старый компьютер. Не подбирайте пароль по ssh — fail2ban забанит IP. Новый ключ потом
добавляется через консоль в `/root/.ssh/authorized_keys`.

**Стоит подумать.** Ключ сейчас без пароля: кто получил файл — получил сервер.
Пароль на ключ ставится одной командой, спросит новый пароль дважды:

```bash
ssh-keygen -p -f ~/.ssh/id_ed25519
```

| `kotu-cert-renew.timer` | — | раз в сутки продлевает сертификат psy3107.ru, когда пора |

Каталоги: `/opt/kotu/{server,public,uploads,library,decks,archive,.env}`, бэкапы `/opt/backups`
(снимки перед каждым деплоем — `/opt/backups/predeploy`, не удаляются).

**Сообщения владелице.** Упала служба `kotu*`, не прошла ночная копия или продление
сертификата, сайт не отвечает, самопроверка нашла неработающую модель, Whisper или почту -
сообщение в Telegram от бота ПСИ (через мост, скрипты `kotu-alert`, `kotu-health`, код
`lib/self-check.ts`). Подробности - `ops/services/README.md`.

**Вторая и третья копии бэкапа.** Всё, что снимается ночью, лежит на том же диске, что и
платформа. Поэтому сразу после ночной копии сервер отправляет её на старый сервер Timeweb
(`/srv/kotu-offsite-backup`, пользователь там может только дописывать), а ещё копия забирается на компьютер автора — сама, каждый день в 13:30
(`~/Library/LaunchAgents/ru.psy3107.backup-pull.plist`, лог в `~/Library/Logs/psy3107-backup.log`).
Вручную — `./ops/pull-backup.sh`. Это зона А: копировать можно только на свой компьютер или
в российское хранилище, за границу — никогда. На компьютере копия только пополняется: дампы,
конфиги, архив файлов и снимки не удаляются и не перезаписываются, даже когда на сервере их
уже нет. Зеркалами сервера остаются лишь `data/{library,uploads,decks}` — и синхронизируются,
только если сервер жив (свежий дамп и каталог архива на месте); иначе скрипт громко
предупреждает `!!! ВНИМАНИЕ` и ничего не удаляет.

**Если сервер умер** — порядок восстановления в `ops/ВОССТАНОВЛЕНИЕ.md`. Репетиция:
`ssh root@СЕРВЕР bash -s < ~/kotu/ops/restore-check.sh` с компьютера (разворачивает свежий дамп во временную базу).

**Правило двух зон:** аудио не покидает сервер (Whisper локальный); текст уходит к моделям
Codex по подписке через мост ПСИ как есть - скрытие имён убрано 18.11.2026, платный ключ OpenAI
выключен (`ARCHITECTURE.md` §10). Транзита больше нет.

## Архив: прежние версии и удалённое

Стирать нельзя ничего (решение владелицы 23.09.2026). «Удалить» в платформе убирает вещь с
экрана, а прежнее содержимое остаётся в архиве:

- **строки** — в базе `kotu`, схема `archive`: `archive.rows` (таблица `tbl`, id строки `row_id`,
  `op` = INITIAL — первичный снимок, один раз на таблицу (отметка в `archive.meta`), UPDATE — версия до правки, DELETE — удалённое, INPUT —
  то, что вводилось руками и больше нигде не лежит: вставленный текст презентации, а при удалении
  колоды, лекции или записи — вход её задач очереди (`data.payload`: указание к переделке слайда
  или образа и т. п.); сама строка — в `data`). TRUNCATE этих таблиц запрещён триггером;
- **файлы** — `/opt/kotu/archive/<первые 2 знака sha256>/<sha256>`, откуда что пришло — в
  `archive.file_events` (к какой записи, документу или колоде, исходное имя файла).

Жив ли архив: `curl -s https://psy3107.ru/api/healthz` → `"archive":"ok"`.
Команды ниже — на сервере (`ssh root@СЕРВЕР`), числа и названия подставить свои:

```bash
# 1. Что происходило последним (у строк INPUT названия нет — вместо него вид задачи)
sudo -u postgres psql -d kotu -c "select id, at, tbl, op, row_id, left(coalesce(data->>'title', data->>'job_kind'), 60) as title from archive.rows order by id desc limit 30"

# 2. Все прежние версии одной расшифровки (id записи — 12). Строки INPUT — не версии,
#    а вход задач (имя файла, настройки): у них нет ни title, ни segments, поэтому здесь их нет
sudo -u postgres psql -d kotu -c "select id, at, op, data->>'title' as title, left(data->>'segments', 300) as text from archive.rows where tbl = 'transcriptions' and row_id = '12' and op <> 'INPUT' order by id"

# 2а. А вход задач той же записи — отдельно
sudo -u postgres psql -d kotu -c "select id, at, data->>'job_kind' as job, left(data->>'payload', 300) as payload from archive.rows where tbl = 'transcriptions' and row_id = '12' and op = 'INPUT' order by id"

# 3. Удалённые лекции по слову из названия
sudo -u postgres psql -d kotu -c "select id, at, row_id, data->>'title' from archive.rows where tbl = 'lectures' and op = 'DELETE' and data->>'title' ilike '%вытесн%'"

# 4. Файлы записи 12 (аудио и библиотечные копии): где лежат в архиве и как назывались
sudo -u postgres psql -d kotu -c "select e.at, e.kind, e.original_name, e.source_path, f.stored_path from archive.file_events e join archive.files f using (sha256) where e.entity_type = 'transcription' and e.entity_id = 12 order by e.at"

# 5. Вернуть файл — НОВЫМ файлом (install создаёт его заново), а не cp поверх: обычный cp в
#    существующий путь пишет в тот же inode, а на нём висят объект архива и снимки деплоя
install -m 0644 -o kotu -g kotu /opt/kotu/archive/ab/abcdef… /opt/kotu/library/возвращённое.pdf
```

⚠️ Файлы в `library`, `uploads`, `decks` не редактировать на месте (vim, `>`, `cp` поверх): это
жёсткие ссылки на объекты архива и снимков — правка испортит и их.

Вернуть удалённую строку целиком (с прежним id; N — `id` из `archive.rows`, таблица — своя):

```bash
sudo -u postgres psql -d kotu -c "insert into public.lectures select * from jsonb_populate_record(null::public.lectures, (select data from archive.rows where id = N))"
```

Дочерние строки (главы, источники, слайды) возвращаются так же, после родителя. Стереть что-то
из архива окончательно может только владелица и только вручную: таблицы архива закрыты
триггером `append_only`, а порядок для запроса пациента на удаление — в `ARCHITECTURE.md` §10.

- Сквозной тест на проде: 10 слайдов, образы нарисованы и приняты, PPTX 3.7 МБ.
- Грабли: Gemini отдаёт JPEG под видом PNG — формат определяется по магическим байтам
  (`sniffImage`); модерация OpenAI может отклонить слишком «анатомичный» сюжет — слайд
  остаётся с ошибкой и кнопкой перерисовки, колода не падает.

## Грабли, на которые уже наступили

- **Шрифты только со своего сервера.** Google Fonts подключался `<link>`-ом и блокировал
  отрисовку: из России запрос висел до таймаута — «сайт не работает без ВПН». Любой внешний
  CDN на странице = платформа недоступна половине пользователей (и нарушение §10).
- `pkill -f` по имени скрипта убивает собственную ssh-сессию — фильтровать иначе.
- Сырой SQL в drizzle отдаёт колонки как `entity_id`, camelCase не появляется.
- Разбор загрузок отдаёт имя файла в latin1 — русские названия ломаются без `decodeUploadName`.
- `dig +short @сервер-реестра домен NS` не показывает делегирование: записи в секции AUTHORITY.
- Модели Gemini непостоянны: часть недоступна новым ключам, часть перестаёт отвечать.
  Поэтому у картинок есть запасная модель.
- После сетевой аварии Timeweb ssh рвёт длинные соединения — долгие операции запускать
  через `setsid nohup` и `python3 -u`.
