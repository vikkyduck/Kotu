```bash
./ops/pull-backup.sh # забрать бэкап с сервера к себе на компьютер

```

Все скрипты спрашивают секреты вслепую и проверяют их живым запросом.

Сборка **только через pnpm** (`~/.local/bin/pnpm`), npm заблокирован хуком.
Миграции БД — drizzle push через ssh-туннель, рецепт в комментарии `deploy.sh`.

## Переезд на другой компьютер

**Бэкапы переносить не нужно** — папка `~/kotu-backups` это копия, а не оригинал.
На новом компьютере она восстанавливается одной командой `./ops/pull-backup.sh`.
Переносить нужно не данные, а ДОСТУП к серверу.

Что забрать со старого компьютера (напрямую — флешка, AirDrop, кабель; не почтой
и не через облако):

1. `~/.ssh/id_ed25519` и `~/.ssh/id_ed25519.pub` — этим ключом открывается и сервер,
   и GitHub. Ключ без пароля, поэтому сам файл и есть доступ.
2. `~/kotu-backups` — только если хотите сохранить историю дампов. Свежий бэкап
   всё равно приедет заново; старые копии нужны лишь на случай «сервер погиб
   раньше, чем я успела скачать».

Что переносить НЕ нужно: код (он на GitHub), секреты (живут в `/opt/kotu/.env`
на сервере и попадают в бэкап), настройки платформы (в базе на сервере).

На новом компьютере:

```bash
mkdir -p ~/.ssh && cp <ключ> ~/.ssh/id_ed25519 && chmod 600 ~/.ssh/id_ed25519
ssh root@5.129.198.180 "echo вход работает"
git clone git@github.com:vikkyduck/Kotu.git ~/kotu
cd ~/kotu && pnpm install
./ops/pull-backup.sh
```

**Если ключ потерялся.** Вход по паролю на сервере разрешён, и в панели Timeweb
есть консоль — значит, вы не заперты снаружи. Но пароль root надо знать заранее:
проверьте его в панели ДО того, как стирать старый компьютер. Новый ключ потом
добавляется в `/root/.ssh/authorized_keys`.

**Стоит подумать.** Ключ сейчас без пароля: кто получил файл — получил сервер.
Пароль на ключ ставится одной командой, спросит новый пароль дважды:

```bash
ssh-keygen -p -f ~/.ssh/id_ed25519
```

## Что на сервере

| Сервис | Порт | Что делает |
|---|---|---|
| `kotu` | 5010 | приложение (nginx отдаёт наружу на 443 и 8091) |
| `kotu-whisper` | 9010 | распознавание речи локально |
| `kotu-privacy` | 9020 | маскировка имён локально (natasha) |
| `kotu-embed` | 9030 | эмбеддинги локально (multilingual-e5-large) — индексация не покидает сервер |
| `kotu-ai-router` | 8444 | маршрутизатор моделей (nginx) |
| `postgresql` | 5432 | база `kotu` |
| `kotu-backup.timer` | — | бэкап каждую ночь в 04:20: дампы базы и конфиги 14 дней, файлы (`library`, `uploads`, `decks`) — зеркалом. Скрипт в репозитории: `ops/kotu-backup.sh` |

Каталоги: `/opt/kotu/{server,public,uploads,library,.env}`, бэкапы `/opt/backups`.

**Вторая копия бэкапа.** Всё, что снимается ночью, лежит на том же диске, что и платформа,
поэтому копия забирается на компьютер автора — сама, каждый день в 13:30
(`~/Library/LaunchAgents/ru.psy3107.backup-pull.plist`, лог в `~/Library/Logs/psy3107-backup.log`).
Вручную — `./ops/pull-backup.sh`. Это зона А: копировать можно только на свой компьютер или
в российское хранилище, за границу — никогда.

**Если сервер умер** — порядок восстановления в `ops/ВОССТАНОВЛЕНИЕ.md`. Репетиция:
`bash ops/restore-check.sh` на сервере (разворачивает свежий дамп во временную базу).

**Правило двух зон:** аудио и имена пациентов обрабатываются только локально и сервер не
покидают. Всё остальное ходит к зарубежным моделям через транзит на дроплете, который принимает
соединения только с этого сервера.

- ✅ **Расшифровка записей** — локальный Whisper, имена маскируются до отправки за границу
- ✅ **Материал ходит между инструментами** (31 июля): готовая лекция и готовая презентация
  сами ложатся в библиотеку текстом и попадают в поиск (`documents.lecture_id` /
  `deck_id`, копия — не вторая карточка, а поисковый след своей работы: живёт и умирает
  вместе с оригиналом, переезжает с ним по папкам, обновляется при правке главы или слайда).

  на основе — источник в форме уже выбран. Поиск по смыслу вынесен человеку:

  лекция и презентация — три действия над ней. Книги, расшифровки, лекции и презентации
  лежат одним списком и раскладываются по общим папкам (`folder_id` есть и у лекций,

## Грабли, на которые уже наступили

- **Шрифты только со своего сервера.** Google Fonts подключался `<link>`-ом и блокировал
  отрисовку: из России запрос висел до таймаута — «сайт не работает без ВПН». Любой внешний
  CDN на странице = платформа недоступна половине пользователей (и нарушение §10).
- `pkill -f` по имени скрипта убивает собственную ssh-сессию — фильтровать иначе.
- Сырой SQL в drizzle отдаёт колонки как `entity_id`, camelCase не появляется.
- Разбор загрузок отдаёт имя файла в latin1 — русские названия ломаются без `decodeUploadName`.
- `dig +short @сервер-реестра домен NS` не показывает делегирование: записи в секции AUTHORITY.
- Модели Gemini непостоянны: часть недоступна новым ключам, часть перестаёт отвечать.
  Поэтому у картинок есть запасная модель.
- После сетевой аварии Timeweb ssh рвёт длинные соединения — долгие операции запускать
  через `setsid nohup` и `python3 -u`.
